# Git 同步规则

本仓库可能同时推送到多个远程仓库，例如 `origin` 和 `computer_design`。同步不同远程时，只关心当前 Java 后端目录 `3-d_object_back/` 的内容。

## 核心规则

1. `3-d_object_back/` 以外的内容，不在本目录同步范围内。
2. 从某个目标远程拉取或接受内容时，`3-d_object_back/` 以外的文件直接以目标远程为准。
3. 推送到某个目标远程时，`3-d_object_back/` 目录内的内容以当前本地版本为准，直接替换目标远程中的同名目录内容。
4. 不要因为同步 `3-d_object_back/` 而合并、覆盖或修正其它目录的差异。

## 推荐操作方式

当需要把本地 `3-d_object_back/` 同步到另一个远程时，推荐在目标远程分支上操作：

1. 基于目标远程分支创建临时 worktree。
2. 只把当前仓库的 `3-d_object_back/` 目录内容应用到临时 worktree。
3. 提交这个目录的变更。
4. 推送临时 worktree 的分支到目标远程。
5. 删除临时 worktree。

这样可以保证：

- 目标远程中 `3-d_object_back/` 以外的内容保持目标远程自己的状态。
- 目标远程中的 `3-d_object_back/` 被当前 Java 后端版本更新。
- 不会把其它远程的前端、AI Python、依赖目录、构建产物等内容互相带过去。

## 注意事项

- 不要使用会把整个仓库历史和文件树混合到一起的普通 merge 来处理跨远程同步，除非明确需要同步全仓库。
- 提交时只暂存 `3-d_object_back/` 下需要纳入版本管理的文件。
- `.DS_Store`、本地环境目录、临时文件、测试输入文件等不应随同步提交。
