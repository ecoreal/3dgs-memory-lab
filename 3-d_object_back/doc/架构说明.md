# 系统架构说明

## 整体架构

本项目采用经典的三层架构模式，结合 Spring Boot 框架的特性，实现了清晰的分层和职责分离。

```
┌─────────────────────────────────────────────────────────┐
│                      前端应用层                           │
│             (React/Vue + Three.js)                      │
└─────────────────────────────────────────────────────────┘
                         ↓ HTTP/REST API
┌─────────────────────────────────────────────────────────┐
│                    Controller 层                         │
│         (接收请求、参数校验、返回响应)                      │
├─────────────────────────────────────────────────────────┤
│                     Service 层                           │
│         (业务逻辑处理、事务管理、数据组装)                   │
├─────────────────────────────────────────────────────────┤
│                   Repository 层                          │
│         (数据访问、JPA 操作、数据库交互)                    │
├─────────────────────────────────────────────────────────┤
│                      Entity 层                           │
│         (数据模型、数据库表映射、实体关系)                   │
└─────────────────────────────────────────────────────────┘
                         ↓ JDBC
┌─────────────────────────────────────────────────────────┐
│                   MySQL 数据库                           │
│         (持久化存储、关系管理、数据查询)                    │
└─────────────────────────────────────────────────────────┘
```

## 各层职责详解

### 1. Controller 层（控制器层）

**职责**：
- 接收 HTTP 请求并解析参数
- 调用 Service 层处理业务逻辑
- 封装响应数据并返回给前端
- 处理异常并返回适当的 HTTP 状态码

**设计原则**：
- 保持 Controller 的轻量化，避免业务逻辑
- 使用 `@RestController` 自动将返回对象转为 JSON
- 使用 `@RequestMapping` 定义路由规则
- 通过 `HttpServletRequest` 获取拦截器传递的用户信息

**示例**：
```java
@RestController
@RequestMapping("/api/models")
public class ModelController {
    @Autowired
    private ModelService modelService;

    @PostMapping("/upload")
    public ModelEntity uploadModel(@RequestBody ModelUploadDTO uploadDto,
                                   HttpServletRequest request) {
        Long currentUid = (Long) request.getAttribute("current_uid");
        uploadDto.getModel().setUid(currentUid);
        return modelService.saveModelWithTags(uploadDto);
    }
}
```

### 2. Service 层（服务层）

**职责**：
- 实现核心业务逻辑
- 管理事务边界（使用 `@Transactional`）
- 协调多个 Repository 完成复杂操作
- 数据转换和聚合

**设计原则**：
- 每个 Service 对应一个业务领域
- 使用 `@Service` 注解标记为 Spring 组件
- 通过 `@Transactional` 确保数据一致性
- 返回业务对象，不直接返回 Repository 查询结果

**示例**：
```java
@Service
public class ModelService {
    @Autowired
    private ModelRepository modelRepository;

    @Transactional
    public ModelEntity saveModelWithTags(ModelUploadDTO dto) {
        ModelEntity model = dto.getModel();
        model.setRenderStatus(RenderStatus.waiting);
        ModelEntity savedModel = modelRepository.save(model);

        if (dto.getTags() != null) {
            modelTagService.addTags(savedModel.getMid(), dto.getTags());
        }
        return savedModel;
    }
}
```

### 3. Repository 层（数据访问层）

**职责**：
- 定义数据访问接口
- 继承 JpaRepository 获得基础 CRUD 能力
- 自定义查询方法
- 使用 `@Query` 注解编写复杂 SQL

**设计原则**：
- 接口继承 `JpaRepository<Entity, ID>`
- 遵循 Spring Data JPA 命名规范自动生成查询
- 复杂查询使用 `@Query` 注解

**示例**：
```java
public interface ModelRepository extends JpaRepository<ModelEntity, Long> {
    List<ModelEntity> findByIsPublicTrue();
    List<ModelEntity> findByUid(Long uid);

    @Query("SELECT m FROM ModelEntity m WHERE " +
           "(:keyword IS NULL OR m.title LIKE %:keyword%) AND " +
           "(:categoryId IS NULL OR m.categoryId = :categoryId) AND " +
           "m.isPublic = true")
    List<ModelEntity> searchPublic(String keyword, Integer categoryId);
}
```

### 4. Entity 层（实体层）

**职责**：
- 定义数据模型
- 映射数据库表结构
- 定义字段约束和关系

**设计原则**：
- 使用 `@Entity` 标记实体类
- 使用 `@Table` 指定表名
- 使用 `@Id` 和 `@GeneratedValue` 定义主键策略
- 使用 `@Column` 定义字段属性

## 核心配置类

### 1. WebConfig（Web 配置）

**功能**：
- CORS 跨域配置
- 拦截器注册
- 静态资源映射

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    // CORS 配置：允许前端跨域访问
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true);
    }

    // 拦截器配置：JWT 认证
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/users/login", "/api/users/register");
    }
}
```

### 2. LoginInterceptor（登录拦截器）

**功能**：
- 拦截需要认证的请求
- 验证 JWT Token
- 将用户信息注入到请求中

**执行流程**：
```
1. 客户端请求携带 Authorization: Bearer <token>
   ↓
2. 拦截器拦截请求（preHandle）
   ↓
3. 提取 Token 并调用 JwtUtils.validateToken()
   ↓
4. 验证成功：将 uid 存入 request.setAttribute("current_uid", uid)
   验证失败：返回 401 Unauthorized
   ↓
5. Controller 通过 request.getAttribute("current_uid") 获取用户 ID
```

### 3. DataInitializer（数据初始化）

**功能**：
- 实现 `CommandLineRunner` 接口
- 在应用启动时自动执行
- 初始化默认分类、用户、模型

**执行时机**：Spring Boot 应用启动完成后

## 认证流程

### 登录流程

```
1. 用户提交 email + password
   ↓
2. UserController.login() 接收请求
   ↓
3. UserService.login() 验证用户凭证
   ↓
4. 验证通过：JwtUtils.generateToken() 生成 Token
   ↓
5. 返回 { token, userInfo } 给前端
   ↓
6. 前端存储 Token（localStorage/sessionStorage）
   ↓
7. 后续请求携带 Token：Authorization: Bearer <token>
```

### 权限验证流程

```
1. 前端发起请求（携带 Token）
   ↓
2. LoginInterceptor 拦截请求
   ↓
3. 解析 Token 获取 uid
   ↓
4. 验证通过：将 uid 注入 request
   验证失败：返回 401
   ↓
5. Controller 获取 uid 执行业务逻辑
   ↓
6. Service 层检查权限（如：model.uid == current_uid）
   ↓
7. 返回响应
```

## 事务管理

### 事务边界

使用 `@Transactional` 注解标记需要事务管理的方法：

```java
@Service
public class ModelService {
    @Transactional  // 方法级别的事务
    public ModelEntity updateModelDetails(Long mid, Map<String, Object> updateMap, Long currentUid) {
        // 1. 查询模型
        ModelEntity model = modelRepository.findById(mid).orElseThrow();

        // 2. 权限检查
        if (!model.getUid().equals(currentUid)) {
            throw new RuntimeException("权限不足");
        }

        // 3. 更新模型
        modelRepository.save(model);

        // 4. 更新标签（如果失败，整个事务回滚）
        modelTagService.deleteTagsByMid(mid);
        modelTagService.addTags(mid, newTags);

        return model;
    }
}
```

### 事务传播机制

- `REQUIRED`（默认）：如果当前存在事务，则加入；否则新建事务
- `REQUIRES_NEW`：总是创建新事务，挂起当前事务
- `SUPPORTS`：如果当前存在事务，则加入；否则以非事务方式执行

## 文件存储架构

### 存储结构

```
项目根目录/
└── uploads/
    ├── avatar/          # 用户头像
    │   └── uuid.jpg
```

### 访问路径映射

- 物理路径：`/path/to/project/uploads/avatar/uuid.jpg`
- URL 路径：`http://localhost:8080/uploads/avatar/uuid.jpg`

### 文件上传流程

```
1. 前端上传文件 → POST /api/upload/{type}
   ↓
2. MultipartFile 接收文件
   ↓
3. 生成 UUID 文件名
   ↓
4. 保存到 uploads/{type}/ 目录
   ↓
5. 返回访问 URL：http://localhost:8080/uploads/{type}/{uuid}.ext
   ↓
6. 前端存储 URL 并显示
```

## 数据流转示例

### 创建模型的完整流程

```
1. 前端提交表单数据
   {
     model: { title, story, categoryId, thumbnailUrl },
     tags: ["复古", "1920年代"]
   }
   ↓
2. ModelController.uploadModel() 接收请求
   - 从 request 获取 current_uid
   - 设置 model.uid = current_uid
   ↓
3. ModelService.saveModelWithTags()
   - 设置 renderStatus = waiting
   - 保存 model 到数据库（获得自增 mid）
   - 调用 ModelTagService.addTags() 保存标签

4. ModelRepository.save() 执行数据库插入
   ↓
5. 返回保存后的 ModelEntity（包含自增 mid）
   ↓
6. 前端跳转到编辑页：/editor/{mid}
```

## 异常处理策略

当前项目使用简单的异常处理：

```java
// Controller 层
try {
    User user = userService.register(nickname, email, password);
    return ResponseEntity.status(201).body(user);
} catch (RuntimeException e) {
    return ResponseEntity.status(400).body(e.getMessage());
} catch (Exception e) {
    return ResponseEntity.status(500).body("系统故障");
}
```

**建议改进**：使用全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(RuntimeException.class)
    public ResponseEntity<?> handleRuntimeException(RuntimeException e) {
        return ResponseEntity.badRequest().body(e.getMessage());
    }
}
```

## 性能优化建议

### 1. 数据库层面
- 为高频查询字段添加索引（uid, mid, categoryId）
- 使用连接池管理数据库连接
- 避免 N+1 查询问题（使用 JOIN FETCH）

### 2. 缓存策略
- 使用 Spring Cache 缓存分类列表
- 使用 Redis 缓存热门模型数据
- 缓存用户信息减少数据库查询

### 3. 异步处理
- 模型渲染任务异步处理
- 邮件发送异步执行
- 使用消息队列处理耗时操作

### 4. 接口优化
- 分页查询避免一次性加载大量数据
- 使用 DTO 减少数据传输量
- 压缩响应数据（Gzip）

## 扩展性设计

### 1. 微服务拆分建议

当业务增长时，可将单体应用拆分为：
- **用户服务**：用户认证、个人信息管理
- **模型服务**：模型 CRUD、文件管理
- **社交服务**：点赞、收藏、评论
- **渲染服务**：3D 模型处理和渲染
- **通知服务**：邮件、站内消息

### 2. 数据库分库分表

- 按用户 ID 分片存储用户数据
- 按时间分片存储日志和评论数据
- 读写分离提升查询性能

### 3. 对象存储

将文件存储从本地迁移到云存储：
- 使用 OSS/S3 存储文件
- CDN 加速文件访问
- 自动备份和容灾
