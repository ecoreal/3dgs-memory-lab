# 安全机制说明

## 概述

本项目采用 JWT (JSON Web Token) 认证机制，结合拦截器实现接口权限控制，确保用户数据和操作的安全性。

## JWT 认证机制

### 1. JWT 工具类（JwtUtils）

**位置**: `src/main/java/com/cqq/_3dobject/utils/JwtUtils.java`

#### 核心功能

**生成 Token**:
```java
public String generateToken(Long uid, String email) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("uid", uid);
    claims.put("email", email);

    return Jwts.builder()
            .setClaims(claims)
            .setIssuedAt(new Date())
            .setExpiration(new Date(System.currentTimeMillis() + EXPIRATION))
            .signWith(KEY, SignatureAlgorithm.HS256)
            .compact();
}
```

**验证 Token**:
```java
public Claims validateToken(String token) {
    try {
        return Jwts.parserBuilder()
                .setSigningKey(KEY)
                .build()
                .parseClaimsJws(token)
                .getBody();
    } catch (Exception e) {
        return null; // Token 无效或过期
    }
}
```

#### 配置参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 签名算法 | HS256 | HMAC SHA-256 |
| 密钥长度 | ≥32 字符 | 保证安全性 |
| Token 有效期 | 24 小时 | 86400000 毫秒 |
| 存储信息 | uid, email | 用户身份标识 |

```java
    }
```

## 拦截器机制

### 1. 登录拦截器（LoginInterceptor）

**位置**: `src/main/java/com/cqq/_3dobject/config/LoginInterceptor.java`

#### 工作流程

```java
@Component
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request,
                            HttpServletResponse response,
                            Object handler) throws Exception {
        // Step 1: 放行 OPTIONS 请求（CORS 预检）
        if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
            return true;
        }

        // Step 2: 提取 Authorization Header
        String authHeader = request.getHeader("Authorization");

        // Step 3: 验证 Token 格式
        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            String token = authHeader.substring(7);

            // Step 4: 验证 Token 有效性
            Claims claims = jwtUtils.validateToken(token);

            if (claims != null) {
                // Step 5: 提取 uid 并注入 request
                Long uid = claims.get("uid", Long.class);
                request.setAttribute("current_uid", uid);
                return true; // 放行
            }
        }

        // Step 6: 验证失败，返回 401
        response.setStatus(401);
        response.getWriter().write("Unauthorized: Invalid or missing token");
        return false;
    }
}
```

#### 关键点

1. **OPTIONS 请求处理**: 避免 CORS 预检请求被拦截
2. **Token 提取**: 从 `Authorization: Bearer <token>` 中提取
3. **用户信息注入**: 将 `uid` 存入 `request.setAttribute()`
4. **统一错误处理**: 返回 401 状态码和错误信息

## CORS 跨域配置

### 配置说明

```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")
            .allowedOriginPatterns("*")            // 允许所有来源
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")                   // 允许所有请求头
            .allowCredentials(true)                // 允许携带认证信息
            .maxAge(3600);                         // 预检请求缓存 1 小时
}
```

### 注意事项

- 生产环境应限制 `allowedOriginPatterns` 为具体域名
- 避免使用 `*` 通配符，提高安全性
- 配合 HTTPS 使用，防止中间人攻击

## 安全最佳实践

### 1. Token 安全

**前端存储**:
```javascript
// 不推荐：localStorage（易受 XSS 攻击）
localStorage.setItem('token', data.token);

// 推荐：HttpOnly Cookie（后端设置）
// 或使用 sessionStorage 并在关闭浏览器时清除
sessionStorage.setItem('token', data.token);
```

**Token 刷新机制**（建议实现）:
```java
// 生成短期访问 Token（15分钟）+ 长期刷新 Token（7天）
public Map<String, String> generateTokenPair(Long uid, String email) {
    String accessToken = generateToken(uid, email, 15 * 60 * 1000);
    String refreshToken = generateToken(uid, email, 7 * 24 * 60 * 60 * 1000);

    Map<String, String> tokens = new HashMap<>();
    tokens.put("accessToken", accessToken);
    tokens.put("refreshToken", refreshToken);
    return tokens;
}
```

### 2. 密码安全

**密码强度要求**:
```java
public void validatePassword(String password) {
    if (password.length() < 8) {
        throw new RuntimeException("密码长度至少 8 位");
    }
    if (!password.matches(".*[A-Z].*")) {
        throw new RuntimeException("密码必须包含大写字母");
    }
    if (!password.matches(".*[a-z].*")) {
        throw new RuntimeException("密码必须包含小写字母");
    }
    if (!password.matches(".*[0-9].*")) {
        throw new RuntimeException("密码必须包含数字");
    }
}
```

**防止暴力破解**:
- 实现登录失败计数
- 连续失败 5 次后锁定账户 15 分钟
- 使用 Redis 存储失败记录

### 3. SQL 注入防护

**正确使用参数化查询**:
```java
// ✅ 正确：使用 @Query 参数绑定
@Query("SELECT m FROM ModelEntity m WHERE m.title LIKE %:keyword%")
List<ModelEntity> search(@Param("keyword") String keyword);

// ❌ 错误：字符串拼接（易受 SQL 注入攻击）
@Query("SELECT m FROM ModelEntity m WHERE m.title LIKE '%" + keyword + "%'")
```

### 4. XSS 防护

**输入验证和输出转义**:
```java

    // ...
}

private boolean isAllowedType(String contentType, String type) {
    if ("avatar".equals(type)) {
        return contentType.startsWith("image/");
    }
    return true;
```

### 6. 日志记录

**记录敏感操作**:
```java
@Slf4j
@Service
public class UserService {

    public User login(String email, String password) {
        User user = userRepository.findByEmail(email);

        if (user == null) {
            log.warn("登录失败：用户不存在 - email: {}", email);
            return null;
        }

        if (!passwordEncoder.matches(password, user.getPasswordHash())) {
            log.warn("登录失败：密码错误 - uid: {}", user.getUid());
            return null;
        }

        log.info("用户登录成功 - uid: {}", user.getUid());
        return user;
    }
}
```

**注意**: 日志中不应记录密码、Token 等敏感信息

## 常见安全问题及解决方案

| 问题 | 风险 | 解决方案 |
|------|------|----------|
| Token 泄露 | 账户被盗用 | 使用 HTTPS + 短期 Token + 刷新机制 |
| 密码明文存储 | 数据库泄露时密码暴露 | 使用 BCrypt 加密 |
| SQL 注入 | 数据库被攻击 | 使用参数化查询 |
| XSS 攻击 | 窃取用户信息 | 输入验证 + 输出转义 |
| CSRF 攻击 | 未授权操作 | 使用 CSRF Token |
| 文件上传漏洞 | 恶意文件执行 | 文件类型验证 + 重命名 |
| 暴力破解 | 账户被破解 | 失败次数限制 + 验证码 |

## 总结

本项目的安全机制围绕 JWT 认证和拦截器权限控制展开，基本满足中小型应用的安全需求。对于生产环境，建议实施上述所有安全最佳实践，并定期进行安全审计和漏洞扫描。
