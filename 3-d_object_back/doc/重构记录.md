# 后端重构记录

## 一、项目配置优化

### 1. 数据库连接改为本地

## 三、文件存储系统重构

这是本次最大的改动。原有的文件系统存在以下问题：
- `FileUploadController` 只负责上传到磁盘，不创建数据库记录
- `ModelFileController` 只负责记录路径到数据库，不处理实际文件
- 上传和记录分成两步调用，容易出现不一致
- 没有下载接口、没有删除接口
- 文件类型只支持固定的 3 种（ORIGINAL_DATA、GLB、OBJ）

### 1. 数据库表结构变更

**表**: `model_files`

| 变更 | 说明 |
|------|------|
| `file_type` 列 | 从 ENUM 改为 VARCHAR(50)，支持任意格式 |
| 新增 `original_name` 列 | 保存上传时的原始文件名 |
| 新增 `file_size` 列 | 保存文件大小（字节） |
| 新增 `content_type` 列 | 保存 MIME 类型 |
| 新增 `created_at` 列 | 上传时间戳 |

### 2. 实体类重写

**修改文件**: `src/main/java/com/cqq/_3dobject/entity/ModelFile.java`

- `fileType` 从枚举类型改为 `String`，不再限制格式种类
- 新增 `originalName`、`fileSize`、`contentType`、`createdAt` 字段
- 支持的格式类型包括但不限于：GLB、OBJ、FBX、STL、3DS、DAE、PLY、IMAGE、AUDIO、VIDEO、PDF、ARCHIVE 等

### 3. 数据访问层更新

**修改文件**: `src/main/java/com/cqq/_3dobject/repository/ModelFileRepository.java`

- 新增 `findByMidAndFileType` 方法：按模型 ID 和文件类型联合查询
- 新增 `deleteByMid` 方法：删除某个模型的所有文件记录

### 4. 服务层重写

**修改文件**: `src/main/java/com/cqq/_3dobject/service/ModelFileService.java`

全部重写，实现完整的文件生命周期管理：

| 方法 | 功能 |

| `uploadFile(mid, file, fileType)` | 上传文件到磁盘 + 创建数据库记录，一步完成 |
| `getFilesByModel(mid)` | 查询某个模型的所有文件 |

## 五、双 Token 认证机制改造

### 1. 改造背景

原系统使用单 JWT Token（24 小时有效期），存在以下问题：
- Token 被盗后风险窗口大
- 无法主动失效（登出、踢下线）
- 刷新逻辑和业务逻辑耦合

改为 **Access Token + Refresh Token** 双 Token 方案，遵循 OAuth / OWASP 推荐实践。

### 2. 方案设计

| Token 类型 | 格式 | 有效期 | 用途 |
|-----------|------|--------|------|
| Access Token | JWT（含 uid, email, sid） | 15 分钟 | 每次业务请求携带 |
| Refresh Token | 随机 UUID（服务端存 SHA-256 哈希） | 15 天 | 仅用于换取新 Token 对 |

核心机制：
- **Refresh Token Rotation**：每次刷新签发全新 Refresh Token，旧的标记为 used
- **重放检测**：已标记为 used 的 Refresh Token 再次出现 → 整个会话所有 Token 吊销
- **BCrypt 密码加密**：注册时加密，登录时 BCrypt matches 验证

### 3. 数据库变更

**新建 `refresh_sessions` 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 自增主键 |
| session_id | VARCHAR(64) | 会话 ID（一次登录产生，刷新时沿用） |
| uid | BIGINT FK | 用户 ID |
| refresh_token_hash | VARCHAR(128) | Refresh Token 的 SHA-256 哈希 |
| status | ENUM | active（可用） / used（已消费） / revoked（已吊销） |
| expires_at | TIMESTAMP | 过期时间 |
| device_info | VARCHAR(255) | User-Agent 设备信息 |
| created_at | TIMESTAMP | 创建时间 |
| last_used_at | TIMESTAMP | 最后使用时间 |

### 4. 配置变更

**`application.properties`**：

```
旧：app.jwt.expiration=86400000       （单 Token 24 小时）

新：app.jwt.access-token-ttl=900000    （Access Token 15 分钟）
   app.jwt.refresh-token-ttl=1296000000（Refresh Token 15 天）
```

### 5. 新增文件

| 文件 | 说明 |
|------|------|
| `entity/RefreshSession.java` | 刷新会话实体，映射 refresh_sessions 表 |
| `repository/RefreshSessionRepository.java` | 按 tokenHash 查找，按 sessionId/uid 批量吊销 |
| `service/AuthService.java` | 登录签发双 Token、Rotation 刷新、重放检测、登出 |
| `dto/LoginResponse.java` | 统一的登录/刷新响应体 |

| 文件 | 变更 |
|------|------|
| `entity/User.java` | `passwordHash` 加 `@JsonIgnore`，接口永不返回密码 |
| `utils/JwtUtils.java` | `generateToken()` → `generateAccessToken(uid, email, sessionId)`，读取 `access-token-ttl` |
| `service/UserService.java` | BCrypt 加密注册，新增 `verifyPassword()`，删除旧 `login()` |
| `controller/UserController.java` | 登录返回双 Token、注册精简响应、新增 refresh/logout/logout-all 接口 |

### 7. 接口变更

| 接口 | 变化 |
|------|------|
| `POST /api/users/login` | 返回 `{accessToken, expiresIn, refreshToken, refreshExpiresIn, userInfo}` |
| `POST /api/users/register` | 返回精简 `{uid, nickname, email}`，不含密码 |
| `POST /api/users/refresh` | **新增**，用 Refresh Token 换新 Token 对 |
| `POST /api/users/logout` | **新增**，吊销当前设备会话 |
| `POST /api/users/logout-all` | **新增**，吊销用户所有设备会话 |
| `GET /api/users/me` | 响应中不再包含 `passwordHash` 字段 |

### 8. 前端适配要点

- 登录后存储 `accessToken` 和 `refreshToken` 两个值
- 业务请求携带 `Authorization: Bearer <accessToken>`
- 监听响应头 `X-Token-Expires-Soon: true`，触发后台静默刷新
- 收到 401 时，用 `refreshToken` 调用 `/api/users/refresh`
- 刷新成功后更新本地存储的两个 Token，重试原请求
- 刷新也失败时，跳转登录页
- 同一时刻只允许一个刷新请求（单飞控制）
