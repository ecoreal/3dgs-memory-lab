## 数据表详细设计

### 1. users（用户表）

**表名**: `users`
**说明**: 存储用户基本信息和认证数据

| 字段名 | 类型 | 长度 | 约束 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| uid | BIGINT | - | PK, AUTO_INCREMENT | - | 用户唯一标识 |
| nickname | VARCHAR | 50 | NOT NULL | - | 用户昵称 |
| email | VARCHAR | 100 | NOT NULL, UNIQUE | - | 用户邮箱（登录账号）|
| password_hash | VARCHAR | 255 | NOT NULL | - | 密码哈希值 |
| avatar_url | VARCHAR | 500 | NULL | - | 头像 URL |
| bio | TEXT | - | NULL | - | 个人简介 |
| created_at | TIMESTAMP | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引**:
- PRIMARY KEY: `uid`
- UNIQUE INDEX: `email`
- INDEX: `created_at`

**建表语句**:
```sql
CREATE TABLE users (
    uid BIGINT AUTO_INCREMENT PRIMARY KEY,
    nickname VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    avatar_url VARCHAR(500),
    bio TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3. models（模型表）

**表名**: `models`
**说明**: 存储 3D 模型的基本信息

| 字段名 | 类型 | 长度 | 约束 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| mid | BIGINT | - | PK, AUTO_INCREMENT | - | 模型唯一标识 |
| uid | BIGINT | - | NOT NULL, FK | - | 所属用户 ID |
| category_id | INT | - | NULL, FK | - | 分类 ID |
| title | VARCHAR | 200 | NOT NULL | - | 模型标题 |
| story | TEXT | - | NULL | - | 模型故事/描述 |
| production_year | INT | - | NULL | - | 生产年份 |
| render_status | ENUM | - | NOT NULL | 'waiting' | 渲染状态 |
| is_public | BOOLEAN | - | NOT NULL | FALSE | 是否公开 |
| thumbnail_url | VARCHAR | 500 | NULL | - | 缩略图 URL |
| created_at | TIMESTAMP | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**枚举类型**:
- `render_status`: `'waiting'`, `'processing'`, `'success'`, `'failed'`

**索引**:
- PRIMARY KEY: `mid`
- INDEX: `uid`
- INDEX: `category_id`
- INDEX: `is_public`
- INDEX: `created_at`

**外键**:
- `uid` REFERENCES `users(uid)`
- `category_id` REFERENCES `categories(id)`

**建表语句**:
```sql
CREATE TABLE models (
    mid BIGINT AUTO_INCREMENT PRIMARY KEY,
    uid BIGINT NOT NULL,
    category_id INT,
    title VARCHAR(200) NOT NULL,
    story TEXT,
    production_year INT,
    render_status ENUM('waiting', 'processing', 'success', 'failed')
        DEFAULT 'waiting' NOT NULL,
    is_public BOOLEAN DEFAULT FALSE NOT NULL,
    thumbnail_url VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_uid (uid),
    INDEX idx_category (category_id),
    INDEX idx_public (is_public),
    INDEX idx_created_at (created_at),
    FOREIGN KEY (uid) REFERENCES users(uid) ON DELETE CASCADE,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 7. social_actions（社交行为表）

**表名**: `social_actions`
**说明**: 存储用户对模型的点赞和收藏行为

| 字段名 | 类型 | 长度 | 约束 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| id | BIGINT | - | PK, AUTO_INCREMENT | - | 行为 ID |
| uid | BIGINT | - | NOT NULL, FK | - | 用户 ID |
| mid | BIGINT | - | NOT NULL, FK | - | 模型 ID |
| action_type | ENUM | - | NOT NULL | - | 行为类型 |
| created_at | TIMESTAMP | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**枚举类型**:
- `action_type`: `'LIKE'`, `'COLLECT'`

**索引**:
- PRIMARY KEY: `id`
- UNIQUE INDEX: `uid, mid, action_type`（避免重复点赞/收藏）
- INDEX: `mid, action_type`（统计用）

**外键**:
- `uid` REFERENCES `users(uid)` ON DELETE CASCADE
- `mid` REFERENCES `models(mid)` ON DELETE CASCADE

**建表语句**:
```sql
CREATE TABLE social_actions (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uid BIGINT NOT NULL,
    mid BIGINT NOT NULL,
    action_type ENUM('LIKE', 'COLLECT') NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE INDEX idx_unique_action (uid, mid, action_type),
    INDEX idx_model_action (mid, action_type),
    FOREIGN KEY (uid) REFERENCES users(uid) ON DELETE CASCADE,
    FOREIGN KEY (mid) REFERENCES models(mid) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 数据关系说明

### 一对多关系

1. **users → models**: 一个用户可以创建多个模型
   - 外键: `models.uid` → `users.uid`

2. **models → model_tags**: 一个模型可以有多个标签
   - 外键: `model_tags.mid` → `models.mid`

3. **models → model_files**: 一个模型可以有多个文件格式
   - 外键: `model_files.mid` → `models.mid`

4. **models → comments**: 一个模型可以有多条评论
   - 外键: `comments.mid` → `models.mid`

5. **categories → models**: 一个分类可以包含多个模型
   - 外键: `models.category_id` → `categories.id`

### 多对多关系

1. **users ↔ models (点赞/收藏)**: 通过 `social_actions` 表实现
   - 一个用户可以点赞/收藏多个模型
   - 一个模型可以被多个用户点赞/收藏

## 查询优化建议

### 1. 常用查询及索引

**获取用户的所有模型**:
```sql
SELECT * FROM models WHERE uid = ?;
-- 已建立索引: idx_uid
```

**获取公开模型列表**:
```sql
SELECT * FROM models WHERE is_public = TRUE ORDER BY created_at DESC;
-- 已建立索引: idx_public, idx_created_at
```

**搜索模型**:
```sql
SELECT * FROM models
WHERE title LIKE '%keyword%'
  AND category_id = ?
  AND is_public = TRUE;
-- 建议添加全文索引: FULLTEXT(title, story)
```

**统计点赞数**:
```sql
SELECT COUNT(*) FROM social_actions
WHERE mid = ? AND action_type = 'LIKE';
-- 已建立索引: idx_model_action(mid, action_type)
```

### 2. 建议添加的索引

```sql
-- 全文搜索索引（MySQL 5.7+）
ALTER TABLE models ADD FULLTEXT INDEX idx_fulltext (title, story);

-- 组合索引优化查询
ALTER TABLE models ADD INDEX idx_public_category_created
    (is_public, category_id, created_at);
```

### 3. 查询性能优化

**避免 N+1 问题**（查询模型及其标签）:
```sql
-- 不推荐：分别查询
SELECT * FROM models;
-- 对每个模型: SELECT * FROM model_tags WHERE mid = ?;

-- 推荐：JOIN 查询
SELECT m.*, GROUP_CONCAT(mt.tag_name) as tags
FROM models m
LEFT JOIN model_tags mt ON m.mid = mt.mid
WHERE m.is_public = TRUE
GROUP BY m.mid;
```

## 数据维护

### 1. 级联删除规则

所有外键都设置了 `ON DELETE CASCADE`，删除主表记录时自动删除关联数据：

- 删除用户 → 自动删除其所有模型、评论、社交行为
- 删除模型 → 自动删除其标签、文件、评论、社交行为

### 2. 数据备份策略

```bash
# 每日备份
mysqldump -u username -p object_3d > backup_$(date +%Y%m%d).sql

# 恢复备份
mysql -u username -p object_3d < backup_20240314.sql
```

### 3. 数据清理

**清理过期的导出任务**（保留最近 30 天）:
```sql
DELETE FROM export_tasks
WHERE status = 'sent'
  AND created_at < DATE_SUB(NOW(), INTERVAL 30 DAY);
```

## 注意事项

1. **字符集**: 确保数据库和表都使用 `utf8mb4` 字符集，支持 Emoji 和特殊字符
2. **时间戳**: 所有时间字段使用 `TIMESTAMP` 类型，自动记录创建时间
3. **密码安全**: `password_hash` 字段存储加密后的密码，不存储明文
4. **文件路径**: URL 字段长度设为 500，足够存储完整的文件路径
5. **级联删除**: 注意级联删除可能带来的数据丢失风险，重要操作前先备份
